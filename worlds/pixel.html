PROJECT AUTOPSY / ENGINEERING NOTES

What’s behind the build?

Not just what a project does. The problem, the trade-offs, the evidence we can check, and what still needs work.

01HaryomixStudent workspace · product reliability+
THE PROBLEM

Study utilities can become scattered across separate sites and tools. The product idea is to make common student tasks easier to reach in one workspace.

THE DESIGN CHOICE

Keep the experience organized around tools and tasks, and avoid presenting a feature as working until its full flow succeeds.

EVIDENCE / LIMITS

Live site: open it and test each tool directly. Generation and provider integrations have required debugging during development, so current functionality must be checked feature by feature. This page does not claim every tool works.

Test the live product ↗
02Hariom AILocal assistant · controlled actions+
THE PROBLEM

A chat answer is not the same as safely completing a computer task. An agent needs boundaries around what it can change and a way to verify the result.

THE DESIGN CHOICE

Structure work as plan → approval → execution → verification, with explicit approval for risky operations and human approval before merging self-improvement changes.

EVIDENCE / LIMITS

The repository is the inspectable source of truth. This portfolio does not claim the agent is fully autonomous or production-ready; inspect the code, tests and current project status before drawing that conclusion.

Inspect implementation ↗
03Hariom’s personal siteStatic web · honest interactions+
THE PROBLEM

A portfolio can look polished while saying little about the person or linking to interactions that do nothing.

THE DESIGN CHOICE

Use lightweight HTML, CSS and JavaScript, project-specific visuals, native disclosure controls, and local interactions rather than pretending a demo is powered by an AI service.

EVIDENCE / LIMITS

The code is available in GitHub. Source-level checks have been performed, but live browser, device, accessibility and performance tests remain separate validation steps.

Inspect this site’s code ↗

Evidence rule: no invented performance numbers, no fabricated user outcomes, and no claim that an unverified feature is finished.
